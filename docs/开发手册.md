# 开发手册

> 给三个月后的自己看。目标只有一个：**改一个小功能，不用重新摸一遍 9000 行。**

---

## 0. 为什么以前改个小功能要很久

不是代码写得烂，是三个地方在反复收税：

| 税种 | 具体表现 | 现在怎么解 |
|---|---|---|
| **找代码** | 375 个函数、9300 行，每次从顶上 grep 起，grep 七八次才落到点上 | `app.js` 顶部有**模块地图**，按「数据 / 导入 / 刷题 / 其它页签 / 账号」分组列函数名 |
| **漏改第二处** | 改默认值忘了改代码回退、加题型忘了服务端白名单、加按钮只改了错题本没改收藏夹 —— 都是「跑起来才发现」 | 默认值收敛成 `DEFAULT_FORM`；列表按钮的三处重复抽成 `drillOne`；剩下的「一处改动牵动几处」写进本文第 3 节 |
| **验证与发版** | 42 套测试要手打循环、还要记 `NODE_PATH`；发版要挪 `data/`、核 sha1、再挪回来 | `node test/run.js` 一条命令；`bash scripts/release.sh` 一条命令 |

改一个小功能的正常节奏应该是：**地图定位 → 对清单确认没漏 → 跑 `run.js` → 发版脚本**。四步，不用回头翻历史。

## 1. 文件职责

| 文件 | 管什么 | 什么时候动 |
|---|---|---|
| `app.js` | 全部前端逻辑（9300 行，一个 IIFE） | 几乎所有功能 |
| `index.html` | 所有页签的 DOM 骨架 + 文案（767 行） | 加元素、改标签、改下拉选项 |
| `styles.css` | 全部样式（1900 行） | 加类名、改布局、改窄屏断点（**760px** 那条） |
| `server.js` | 静态托管 + 接口表 + 分享码门禁 + 403 白名单 | 加接口、改清洗规则、改门禁 |
| `pay.js` | 付费（冲刺报告 ¥9.90），读 `data/pay*.config.json` | 改价格、改权益 |
| `watcha-oauth.js` | 观猹 OAuth 授权码 + PKCE，服务端换 token | 改登录 |
| `mailer.js` | 零依赖 SMTP，把「提建议」发到站长邮箱 | 改收件人、改发信 |
| `test/` | 42 套回归 + `_harness.js`（公共骨架）+ `run.js`（跑分器） | 每次改功能 |
| `data/` | 配置与运行数据。**只有 3 个文件该跟着发版**，见第 5 节 | 几乎不动 |

> `vendor/` 里是第三方脚本（二维码等），一律本地化，不走 CDN。

## 2. 三条命令

```bash
cd finals-quiz

node test/run.js                 # 跑全部 42 套，全绿才往下走
node test/run.js fav delq        # 只跑名字里带 fav / delq 的（改哪儿跑哪儿）
node test/run.js --quiet         # 只打汇总和失败项

bash scripts/release.sh          # 发版：挪 data → commit → push → 部署 → 核验 → 挪回
```

`run.js` 会自动找 `happy-dom`，**不用再设 `NODE_PATH`**。失败时会直接把 `✗` 那几行贴出来，不用自己翻。

## 3. 常见任务：要动哪几处

> 这一节是本文最该看的部分。每一条都是「只改一处、跑起来发现不对」换来的。

### 3.1 加一个筛选条件

以错题本的 `#wFilter` 为例：

1. `index.html`：`#wFilter` 里加一个 `<option>`
2. `app.js` `renderWrong()`：加一个 `if (f === 'xxx') return ...` 分支
3. 如果这个筛选会被「导出 / 分享 / 跨页跳转」用到：`switchView` 里同步
4. `test/` 里对应那套加断言

**坑**：`f` 取值从 `$('#wFilter').value` 现读，没有默认值兜底 —— 新增 option 后老用户浏览器里可能是空值，记得给 `|| 'all'`。

### 3.2 列表里加一个按钮

列表有**三套**：错题本 `renderWrong()`、收藏夹 `renderFav()`、统计薄弱题（在 `renderStats()` 里）。它们各自拼 HTML，长得很像但不是同一个函数。加按钮要：

1. 三个 `renderXxx()` 里都加按钮 HTML（**这是最容易漏的一处**）
2. 写一个 `bindXxxButtons()`（参考 `bindDelButtons` / `bindFavButtons`），在里面 `$$('#list [data-xxx]').forEach(...)` 绑事件
3. 每个渲染函数的末尾都要调一次这个 bind（`renderFav` 里已有 `bindFavButtons(); bindDelButtons();`）
4. `styles.css`：`.item .btn` 那组；**760px 以下要 `flex-wrap`**，否则窄屏按钮会溢出白卡片
5. 如果动作是「删 / 清空 / 覆盖」，**必须用 `askConfirm`，不能用 `window.confirm`**

### 3.3 改默认出题形式

两个地方，必须同时改：

1. `app.js` 常量 `DEFAULT_FORM`（文件开头，紧挨 `FQ_VERSION`）
2. `index.html` 里 `#qForm` 和 `#rForm` 两个 `select` 的 `selected`

**为什么两处**：HTML 决定新用户看到什么，`DEFAULT_FORM` 决定「localStorage 里没这个值时」代码往哪兜。只改一处会出现「下拉显示 A、实际按 B 出题」。

三个调用点已经都用常量了，别再写字面量 `'choice'`。

### 3.4 加一种题型

**五处**，漏任何一处都会静默降级：

1. `app.js` `FIX_TYPES`（改题面板允许的题型）
2. `app.js` `TYPE_LABEL`（显示名）
3. `index.html` 两处题型下拉（题库筛选 + 手动加题）
4. `server.js` `Q_TYPES` —— **漏这里最阴**：前端看着正常，一存到服务端就被 `cleanQuestions` 降级成 `single`，广场里别人拿到的是单选
5. `decideForms()` / `reciteForm()` 里的判定（新题型给不给选项）

顺手加测试：`test/typesel.test.js` 和 `test/importreport.test.js` 已有类似用例。

### 3.5 改题目的数据结构（加字段）

一条链上有五个口子，都要过一遍：

1. `saveQuestionsToBank()` —— 写入
2. `exportBankJson()` / `exportBankMd()` —— 导出
3. `mergeBanks()` —— 云同步合并（**并集，只增不减**）
4. `server.js` `cleanQuestions()` —— 广场分享时的字段白名单（不加进去，分享出去就丢）
5. `test/` 里造数据的 `bank()` —— 新字段补进样本

**坑**：这五处只要漏一处，表现都是「本地好好的，分享/同步/导出后就没了」，而且不会报错。

### 3.6 加一个服务端接口

1. `server.js` 顶部那张路由表，加 `'POST /api/xxx': async function (req, res) {...}`
2. 前端用 `api('POST', '/api/xxx', body)`（`app.js` `function api`）
3. 需要登录就取当前用户（看 `/api/sync` 怎么校验的）
4. **接口要放在 403 白名单之外**：`server.js` 里 `topDir === 'data'` 与那几个 `.js` 文件名是硬拦的，别把新文件放进 `data/`
5. `test/api.test.js` 里加一组

### 3.7 改文案 / 发公告

- 页面上的字：`index.html`（大部分）+ `app.js` 里拼出来的那些（搜文案原文）
- 站内公告：`app.js` 的 `NOTICE = { id, title, lead, items }`
  - **`id` 一变才会重弹一次**，别用时间戳当 id（每次都弹）
  - 地址文案用 `location.host`，**绝不写死域名**（换过三次域名了）
  - 三条关闭路径都要记已读

## 4. 六条必查的坑

每条都真踩过，改之前对一眼：

1. **`window.confirm` / `window.prompt` 在沙箱 iframe 里被静默吞掉** —— 返回 `false`，用户点「删除」什么都不会发生。一律用站内 `askConfirm`。判断「点了没反应」先查这个。
2. **先取 `input.files` 再清 `value`，FileList 会被就地清空** —— Chromium/Edge 行为，happy-dom 测不出来。先 `slice` 拷成数组再清。
3. **云同步是并集**（`mergeBanks` 本地优先 + 远端补回）—— 光删本地没用，下次拉取会复活。删除必须留墓碑 `fq_gone_v1`，键是 `题集键|题号`，并立刻 `flushPush()`。
4. **题型白名单在服务端也有一份**（`Q_TYPES`）—— 见 3.4。
5. **三平行数组** `S.quiz = { list, forms, results }` —— 删题要在同一个循环里三个一起摘，游标还要往前挪。参考 `deleteQuestionById()`。
6. **删题只删当前这一本** —— 传了 `bankId` 就只动那一本，别本里同题号那份不动。这是产品规矩，不是技术选择。

## 5. 测试怎么写

新测试用 `test/_harness.js`，别再抄那 30 行初始化：

```js
'use strict';
const T = require('./_harness');
const { ok, openWin, bank, seedFor, $, txt } = T;

// 造一本题集（n 道填空题）+ 灌进 localStorage
const { win, api, d } = openWin(seedFor(bank(5, { course: '测试课' })));

ok(api.state().banks.length === 1, '只载入一本');
ok(txt($(d, '#someEl')).indexOf('预期') >= 0, '界面上出现了预期文字');

T.done('这套测什么');   // 打印汇总 + #RESULT 行 + 按失败数退出
```

要点：

- `_harness` 会自动补 `happy-dom` 的查找路径，`node test/xxx.test.js` 直接能跑
- `T.done()` 会打一行 `#RESULT pass=N fail=M` 给 `run.js` 解析，**不要再自己 `console.log` 摘要 + `process.exit`**
- 老测试（还没迁移的）保持原样，`run.js` 认得六种摘要格式，不会漏
- 造数据一律走 `T.bank(n, opts)`，字段和真实题库一致（加了新字段记得同步，见 3.5）

## 6. 发版

```bash
bash scripts/release.sh "v1.23.0 一句话说明"
```

它会依次做：挪走 `data/` 三个非白名单文件 → `git add/commit/push` → 部署 →
curl `/api/version` + 三件套 sha1 核验 + 403 检查 → **把 `data/` 挪回来**（失败也会挪）。

### `data/` 的铁律

`data/` 有 `.gitignore`，但**部署是整目录打包**。只有三个文件该跟着发版：

- `pay.config.json`（`pay.js` 读）
- `watcha-oauth.config.json`（`watcha-oauth.js` 读）
- `mail.config.json`（`mailer.js` 读）

`pay.live.config.json`、`pay.sandbox.config.json`、`.watcha-agent-token`、`users/stats/feedback` 等
**一律发前挪走、发后挪回**。忘了挪，等于把密钥和数据一起发到公网。

### 几点经验

- 部署报 `SITES_START_FAILED` **不等于没上线**：先 curl `/api/version`，通了就是新版本，别急着重试
- **自定义域名暂时拿不到**：`domainPrefix` 只是「想要」，平台按会话 ID 给域名。
  先用 `https://<prefix>.app.workbuddy.host/` 探一下：`404 链接已失效` = 空闲、`403 链接不完整` = 被别人占了
- 线上核验固定四项：`/api/version`、页脚版本号、三件套 sha1、`/data/*` 与那几个 `.js` 是否 403
- 改了判分口径 / 链接 / 收费 → 必须发站内公告，不能只在推文里说

## 7. 版本号

四处必须一致（发版脚本会核）：

1. `package.json` 的 `version`
2. `app.js` 的 `FQ_VERSION`
3. `index.html` 页脚 + 缓存戳 `?v=`
4. `styles.css` / `app.js` 的引用参数

页脚由 `stampVersion()` 用 `FQ_VERSION` 覆盖写一遍 —— 所以用户看到版本号，就说明浏览器真拿到新脚本了。
